# AIFactory 0.2.0 GitHub Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the verified architect-first implementation as the GitHub-only AIFactory 0.2.0 release with final, honest release notes.

**Architecture:** A small documentation-only preparation branch converts the merged release candidate into final release metadata and supplies a tracked GitHub release body. The exact merged `main` commit then passes release-critical checks before an annotated tag and a non-draft GitHub release are created under separate approvals.

**Tech Stack:** Git, GitHub CLI, Python 3.10+, `uv`, pytest, Ruff 0.16.0, setuptools, the repository public-content scanner.

## Global Constraints

- Publish only a GitHub tag and GitHub release; do not publish to PyPI or any other package registry.
- Tag name, package metadata, CLI version, changelog, and release notes must agree on `0.2.0`.
- Use publication date `2026-08-09` throughout final release metadata.
- Preserve the existing compatibility and threat-model language: Contract v1 and `verdict_v1` are deprecated v0.x paths, and the autonomous builder remains experimental.
- Never bypass protected `main`, required checks, public-content scanning, or secret protection.
- Treat branch push, pull-request creation, pull-request merge, tag creation/push, and GitHub release creation as separately approved shared-state actions.
- If the candidate commit changes, rerun every identity, test, build, public-boundary, and provenance check that depends on it.
- Do not delete or move any unexpected existing tag.

- [ ] **Step 3: Add the exact GitHub release body**

Create `.github/releases/0.2.0.md` with this content:

```markdown
# AIFactory 0.2.0 — architecture before code

AIFactory 0.2.0 changes the experimental autonomous builder from a workflow in
which models could appear to grant approval into one where deterministic
controller policy owns every authority-bearing transition.

## Highlights

- **Contract v2:** non-trivial work declares scope, non-goals, risks,
  ambiguities, invariants, failure modes, irreversible effects, dependencies,
  and acceptance coverage before implementation.
- **Exact approvals:** contracts and T2 plans are approved by canonical SHA-256
  digest; plan authority is also bound to the parent contract digest.
- **`findings_v2` judge redesign:** review models emit typed findings as sensors;
  deterministic routing owns `PASS`, `REVISE`, and `BLOCK` dispositions.
- **Replayable controller evidence:** redacted, digest-chained decisions and
  exact pending/accepted artifacts support fail-closed semantic replay.
- **Safer public releases:** current-tree and reviewed-history scans reject
  private operational material, credentials, unsafe links, and unexpected
  artifacts before publication.

## Why this release

An implementation can be internally coherent and still solve the wrong
problem. This release freezes accepted intent before code and prevents names,
labels, or model-authored prose from standing in for authority over changed
artifacts.

## Compatibility and limits

Contract v1 and `verdict_v1` remain deprecated compatibility paths during the
0.x line. Deterministic control does not prove that a contract is true or that a
model sensor found every defect. The builder remains experimental and requires
human review, protected branches, isolation, and least-privilege credentials for
important work.

This is a source-only GitHub release; it is not published on PyPI.

Install the source release directly from GitHub:

```bash
pip install "git+https://github.com/BrainMatterStudios/AIFactory.git@0.2.0"
```

Read the [complete release notes](https://github.com/BrainMatterStudios/AIFactory/blob/0.2.0/docs/releases/0.2.0.md) for migration guidance, reasoning, threat model, attribution, and operating limits.
```
